# Claude Rewind 插件 — 修复与维护指南

> 本文档写给未来的维护者（包括更新 claudecodeui 之后的你/少爷/Claude）。
> 目标：**更新 claudecodeui 后功能消失时，照着本文档一步步做就能恢复。**

## 功能说明

在聊天界面每条用户消息旁注入「⟲」按钮（hover 显示）。点击后：

1. 把会话转录截断回该消息之前（该消息及其后的对话被丢弃）
2. 把 Claude 改过的文件恢复到该消息执行前的状态（利用 CLI 的文件快照）
3. 页面自动刷新显示截断后的历史

等价于 CLI 的 `/rewind`（选「回到此消息之前 + 恢复文件」组合）。

## 文件结构

## 工作原理

### 数据从哪来

| 数据 | 位置 | 说明 |
|------|------|------|
| 会话转录 | `~/.cloudcli/auth.db` 的 `sessions` 表 `jsonl_path` 列 | 每行一个 JSON 条目，含 uuid/parentUuid 链 |
| 消息定位 | 转录中 `type:"user"` 且有 `uuid` 的条目 | 前端传 `data-message-timestamp` + 文本前缀；匹配用 `normalizeForMatch()`（两侧去 markdown 符号+折叠空白再比），失败降级为仅时间戳匹配。同刻多条=编辑产生的兄弟分支，取**后代最多**者（活跃分支） |
| 截断 | 重写 jsonl：丢弃目标消息及全部后代，保留祖先链 | 写前先备份 `.bak-rewind-<ts>` |
| 文件快照 | `~/.claude/file-history/<sessionId>/<hash>@v<N>` | 由 CLI 的 `enableFileCheckpointing` 产生 |
| 快照记录 | 转录内 `file-history-snapshot` / `file-history-delta` 条目 | snapshot.trackedFileBackups: 路径→备份名 |

### 关键机制

- **快照语义（2026-08-26 逆向确认）**：`snapshot(M).trackedFileBackups` 记录的是
  M 所在回合**开始前**的全量文件状态。快照条目物理写入位置在回合中部，但语义
  归属回合起点。`backupFileName: null` 表示该时刻文件**不存在**（新建文件的记录方式）；
  `delta(M, base=S, path)` 表示基于快照 S 的单路径变更。
- **恢复算法（buildRestorePlan）**：
  1. 在目标回合内（目标条目到下一个 user 之间）找第一个 snapshot——即目标回合开始前的状态（最准）
  2. 回合内无 snapshot → 取目标之前最后一个 snapshot 为基 + 其后 delta 依次应用
  3. 表中路径：有备份→从 file-history 恢复；null→现存则删除
  4. 目标之后才出现的跟踪路径→删除
- **兄弟分支消歧**：用户在 CLI 编辑消息会产生同 timestamp+text 的多个条目，
  各在不同分支。取后代计数最大者即 UI 当前显示的活跃分支。
- **消息定位匹配**：前端气泡 textContent 是 markdown 渲染后的文本（符号丢失），
  必须与转录原文两侧都经 `normalizeForMatch()`（去 markdown 符号+折叠空白）再比对；
  失败降级为仅时间戳匹配。

## 更新 claudecodeui 后如何恢复

### 会消失的部分

只有一处源码补丁会被更新覆盖：

**文件** `server/modules/providers/list/claude/claude-runtime.provider.js`
**位置** `mapCliOptionsToSDK()` 函数内、`sdkOptions.tools = ...` 那行之后
**加一行**：

```js
sdkOptions.enableFileCheckpointing = true;
```

没有这一行，CLI 不产生文件快照 → 文件恢复功能静默失效（对话截断仍可用）。

**恢复方法一（推荐）**：运行本插件自带的恢复脚本：

```bash
bash ~/.claude-code-ui/plugins/claude-rewind/patch/apply-rewind-patch.sh
```

脚本幂等（已打补丁会自动跳过），并额外检查 server.js 依赖的宿主
node_modules/better-sqlite3 是否还在。push-to-talk 的
apply-push-to-talk-patch.sh 第 [6/6] 步是同一处补丁，两者用哪个都行。

**恢复方法二**：手动把上面那行加回去。

### 不会消失的部分

插件本体（index.js / server.js / manifest.json）在
`C:\Users\<用户名>\.claude-code-ui\plugins\claude-rewind\`，
claudecodeui 更新不会碰它。装好后到 设置 → Plugins 里确认开关是开的。

### 迁移到别的电脑

1. 拷贝整个 `claude-rewind/` 文件夹到那台机器的同目录
2. 改 `server.js` 里 `resolveHostNodeModules()` 返回的路径 → 指向那边 claudecodeui 的 node_modules
3. 运行 `patch/apply-rewind-patch.sh <那边项目根目录>` 打快照补丁
4. 设置 → Plugins 启用

## 已知限制

- 只支持 provider=claude 的会话（其他 provider 无 file-history 快照）
- 正在流式输出时点回退：截断的是当时磁盘上的转录，正在写的 turn 可能在刷新后重现——最好等回复完再操作（前端目前未拦截）
- 回退后 CLI 侧上下文在**下次发消息**时才真正变短（resume 读截断后的转录）
- 消息定位依赖 `data-message-timestamp`（ISO 字符串）精确匹配 + 归一化文本前缀；
  时间戳对但内容匹配不上时自动降级为仅时间戳——若同刻有多条编辑分支，取活跃分支。
  历史教训：直接用原始文本 startsWith 会因 markdown 渲染失配（**bold**→bold 等），
  曾导致「转录中找不到这条消息」，2026-08-26 修复。

## 排错速查

| 症状 | 原因 | 处置 |
|------|------|------|
| 回退失败：转录中找不到这条消息 | 时间戳/前缀匹配全失败（旧版插件）或会话无转录行 | 更新到含 normalizeForMatch 的 server.js；确认 DB 里该 session 的 jsonl_path 存在 |
| 回退完成但文件没恢复 | ① 无快照：enableFileCheckpointing 补丁缺失，或该消息之前没有快照条目；② 文件是用 Bash 命令建的（echo > 等）——CLI 只跟踪 Write/Edit 工具的改动，Bash 写盘不产生快照，无法恢复 | 打补丁后新对话才有快照；测试时让 Claude 用「创建文件」工具而非 shell 命令 |
| 相对路径的文件恢复报错 | 旧版未解析 cwd（2026-08-26 已修：handleRewind 从转录条目 e.cwd 推断工作目录） | 更新 server.js |
| 点按钮无反应 | 插件未启用或前端未注入 | 设置 → Plugins 确认开关；F12 Console 看报错 |
| 按钮看不见/像刷新 | 旧版 ⟲ 字符 hover 才显示（已改常显 35% 透明度 + SVG 回退图标） | 更新 index.js 到含 SVG 图标版本，F5 刷新 |

## 重要认知：哪些文件改动可被恢复

CLI 的 file checkpointing **只跟踪 Write/Edit/NotebookEdit 等文件工具**：
- ✅ Claude 用「创建/编辑文件」工具写的文件 → 有快照 → 可恢复/删除
- ❌ Claude 用 Bash 命令（`echo >`、`npm install` 等）产生的磁盘变化 → 无快照 → 无法恢复
- 测试方法：让 Claude「在 D:/test 创建 hello.txt」（走 Write 工具），聊几句后回退到创建前，
  hello.txt 应消失并在 toast 里显示「移除 1 个新建文件」。

## 验证方法

1. 让 Claude 改一个测试文件并多聊几轮
2. hover 早先某条用户消息 → 点 ⟲ → 确认
3. 检查：页面刷新后消息变少；测试文件内容回到改前状态；
   转录 jsonl 同目录出现 `.bak-rewind-*` 备份

## 自动测试（改 server.js 后先跑这个）

```bash
cd ~/.claude-code-ui/plugins/claude-rewind
node --test tests/server.test.js
```

覆盖 server.js 的全部纯逻辑（18 例）：消息定位（归一化前缀匹配、兄弟分支选活跃、
仅时间戳兜底）和恢复计划（回合内快照优先、前置快照+delta 顺序应用、新建文件删除、
相对路径 cwd 解析、无快照兜底）。

**为什么 server.js 能 import 测试**：文件顶部有 `IS_MAIN` 守卫——只有宿主以
`node server.js` 启动时才创建 HTTP 服务；其他模块（如测试）import 纯函数不会起监听。
改 server.js 后记得跑测试 + `node server.js` 确认仍输出 `{"ready":true,...}`。
